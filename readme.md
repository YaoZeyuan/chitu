# 潜伏之赤途 · 网页版

《潜伏之赤途》是橙光游戏平台（66rpg）的经典文字冒险游戏（游戏 ID 2992）。游戏当年因题材原因被平台下线，作者本人也遗失了原稿，网上仅存加密的二进制数据文件 `game.bin`——只能运行在橙光播放器里，靠人力几乎不可能还原。

本项目用 AI 辅助逆向，把加密剧本**无损还原为结构化 JSON**，并在此基础上做了三件事：**可完整游玩的网页版**、**可阅读的剧情速览**、**可视化的全剧情分支图**。

- 在线访问：**https://chitu.yaozeyuan.online**
- 背景故事：《[潜伏之赤途 web 版：意外的国庆献礼](https://mp.weixin.qq.com/s/Te_AzcAWIW1AAXgz5UhGgA)》（为什么做、怎么用 AI 做的）

## 一、使用指南

### 访客：三个页面

| 页面 | 地址 | 怎么用 |
|---|---|---|
| 游戏本体 | `/` → `/game` | 和原版橙光玩法完全一致，选项即分支。所有资源已本地化，可离线运行 |
| 剧情速览 | `/plot` | 把 8558 条游戏事件排成可阅读的剧本：按章节分页、下拉跳章、选项可展开看分支内容、面包屑记录访问路径、"返回"优先走浏览器历史 |
| 剧情分支图 | `/plot/branch` | 一张图看懂全剧情结构：顶栏快捷按钮切换序章~第六章（每章一棵树，自动定位到本章开头）；点击任意节点弹出详情（来源/去向、跳转关系、"进入速览"直达对应选项位置）；支持缩放、微缩图、节点定位下拉 |

**图例**：红底白字=入口 · 蓝边=章节标题 · **红色=剧终**（该分支抵达 GAME OVER）· 浅紫菱形=条件判断（好感度等数值门槛）· 绿色边=跨章节跳转 · 黄色=含结局标记

### 开发者：本地运行

```bash
pnpm install      # 安装依赖
pnpm dev          # 开发服务器 http://127.0.0.1:3070
pnpm build        # 构建输出到 dist/
pnpm preview      # 本地预览构建产物
```

数据流水线脚本均为幂等可重跑的 Python，重跑 `build_data.py` + `build_branches_json.py` 即可从 `game.json` 重新生成全部前端数据。

## 二、实现过程：问题 → 思考 → 解决 → 收益

> 本项目从逆向到可视化全程与 AI 协作完成，以下按实际推进顺序记录每个阶段遇到的问题与决策。

### 1. 加密剧本的无损还原

**问题**：`game.bin` 是橙光私有 ORGDAT 格式，只能在官方播放器中运行；游戏下线后原稿丢失，这是"数字灭绝"的典型案例。

**思考**：与其硬啃加密算法，不如利用播放器本身——官方 `main.min.js` 里就有完整的解析逻辑。给播放器打补丁，让它把解密结果导出而不是渲染。

**解决**：AI 分析 `main.min.js` 后打补丁，将 `game.bin` 无损导出为 `resource/game_raw.json`（66 个剧情、8558 条事件）；再用脚本按语义二次清洗为对话（带说话人）/旁白/选项组/跳转/条件/图片/音频分类结构。

**收益**：原作者都丢失的剧情数据被完整抢救为开放格式；后续所有功能（速览、分支图）都建立在这份数据之上。

### 2. 从静态站点到可统计的工程化项目

**问题**：初版是纯静态目录，无法接入访问统计；游戏页、速览页各自为政，路径跳转容易丢失 URL。

**思考**：需要单页应用的客户端路由才能让 analytics 正确统计 PV，但游戏本体是重 JS 逻辑的既有代码，不宜重写。

**解决**：改造为 **Vite + pnpm + Vue 3 多页应用（MPA）**——每页独立入口配 vue-router，游戏逻辑原样保留只做入口包装；Vercel 部署（`cleanUrls` + `/plot` 重写规则），全站接入 `@vercel/analytics`。期间解决过 Vercel rewrite 与 Vite dev server 行为不一致、Windows Hyper-V 端口占用等工程问题。

**收益**：既保住了"游戏逻辑零改动"，又获得了现代前端的构建、路由与统计能力。

### 3. 剧本分支图：从"画不出来"到"一眼看懂"

这是花时间最多、迭代最多的部分，用 [AntV G6](https://g6.antv.antgroup.com/) 渲染，前后解决了四类问题：

**问题 A：分支结构爆炸**。剧本中选项嵌套可达 5 层，深层选项块内容大量重复出现，图根本没法看。

**思考**：图的粒度应该是"章节/节点"而非"每段对话"；超过一定深度的嵌套本质上是子剧情，应当独立成节点。

**解决**：嵌套超过 3 层的选项块用**不动点迭代**拆为独立节点（拆出的块内部可能仍有深嵌套，反复拆直到无新增）；反之，"无跳转目标但只有几段对话"的纯信息展示节点（481 个，如图书馆问答）自动过滤不上图。节点数从失控收敛到 **235 节点 / 335 边**。

**问题 B：剧终语义不精确**。像"夜总会"这样的大章节，只是其下的某个选项分支（安四贤砍头戏）抵达了 GAME OVER，整个章节节点却被标成剧终。

**思考**：剧终是"分支"的属性，不是"章节"的属性。判定必须区分"顶层直接结局"与"选项块内结局"。

**解决**：数据层统计 `direct` 字段（只计选项块之外的 game_over）；选项块内抵达的结局归属到对应的合成分支节点。剧终 = 含直接结局且不跨章跳转 → 红色。

**问题 C：条件跳转不可见**。好感度门槛（`友好度 < 8` → 跳转）这类数值分支在图上完全隐形。

**解决**：扫描"条件后紧跟跳转"的配对模式（451 个条件中仅 20 个真正起分流作用），生成菱形节点嵌入图流程，与剧情节点形状区分。

**问题 D：G6 工程坑**。第三方库 mixed ESM/CJS 里的裸 `require("../package.json")` 导致线上构建崩溃（`commonjsOptions.transformMixedEsModules` 解决）；`fitView: true` 异步二次缩放覆盖手动视图（改用 `afterlayout` 事件手动控制）；`G6.Arrow.triangle` 是函数须传路径字符串等。

**收益**：一张 235 节点的图完整覆盖了原作全部剧情流——章节树划分、剧终红色预警、条件菱形、跨章绿色跳转，配上锚点直达速览对应选项的联动，玩家攻略和剧情研究都能直接用。

### 4. 阅读体验的细节修复

对话丢失说话人（3215 条旁白与 5052 条对话混在一起）→ 追溯到数据重建脚本丢弃了 `Argv[0]` 字段，修复后 2284 条对话恢复了说话人；速览页相对路径跳转丢失 URL、浏览器历史回退语义、拆分节点页的"智能返回"（优先 `history.back()`，无历史才按父章节跳转）等，逐个打磨。

### 总体收益

- **文化存档**：原作者已遗失的剧情数据被完整抢救并开放为 JSON / Markdown，任何人可检索、二创；
- **方法论验证**：验证了"AI 逆向加密数据 + 人类把握产品形态"的协作模式——初版转换仅 4 轮对话、最低价档模型完成（见公众号文章），后续迭代聚焦在数据语义化与可视化打磨上；
- **可复用流水线**：从二进制到分支图的整条数据管线幂等可重跑，同类橙光游戏可直接复用。

## 三、项目结构

```
├── index.html / game.html      # MPA 构建入口（导航页 / 游戏页）
├── plot/                       # 剧情速览 & 分支图页面模板
├── public/                     # 静态资源根（游戏本体 + 剧本数据 + plot JS）
│   ├── data/game.json          # 播放器实际加载的结构化剧本
│   ├── graphics/ audio/ font/  # 本地化的游戏资源（381 个，无外部依赖）
│   └── plot/js/                # data.js(速览+图共用) / branches.json(分支图) / viewer.js
├── src/                        # Vue 入口与路由、branch-main.js(G6 分支图)
├── glm-5.3-flash/game.json     # rebuild_game_json.py 的输出(语义化事件)
├── task_plan/                  # 数据流水线脚本与任务记录
└── resource/                   # 可读版剧本、原始 game_raw.json、资源 URL 映射
```

数据流水线四步：`game.bin` →(播放器补丁)→ `game_raw.json` →(语义化)→ `game.json` →(build_data.py：拆分/合成/菱形)→ `data.js` →(build_branches_json.py)→ `branches.json`。

## 四、部署

托管于 Vercel（`vercel.json`：输出 `dist/`、cleanUrls、`/plot` 重写），推送 master 后自动部署；全站接入 `@vercel/analytics` 统计。早期 GitHub Pages 方案见 `DEPLOY.md`。
