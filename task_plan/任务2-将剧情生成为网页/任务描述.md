## 评审记录（2026-10-06）

**结论：两个需求均可行，数据源充足，无硬伤。**

### 数据基础盘点
- `glm-5.3-flash/game.json`：结构化数据，66 个剧情，事件带类型标注（narration 8267 / dialogue 291 / choice 812 / jump 129 / if 168 / game_over 139 / show_pic 1099 等），是两个网页的理想数据源
- 资源：`site/graphics/background/`（237 张被引用图片中 224 张存在）、`site/audio/bgm|se/`
- 背景图映射：show_pic 引用如 `Background/轮船1.jpg` → 实际文件 `site/graphics/background/轮船1.jpg`，目录名大小写需映射，文件名中文需 encodeURIComponent

### 需求1（剧情速览版）：可行，工作量中等
- 按背景图分组展示对话列表、遇选项停止：渲染逻辑直接，数据完全支持
- 选项跳转 + 浏览器历史 + URL 带 id：用 `?s=<剧情ID>&i=<事件索引>&p=<压缩路径>` 即可，history.pushState/hash 均可
- 复杂点①：条件分支（if/elseif 168 处）的跳转目标取决于运行时变量值（如 `[015:只求自保的回答]`），无法静态确定唯一路径。建议速览版把所有分支都平铺展示并在条件处标注条件文本，不做变量模拟
- 复杂点②：224/237 图片存在，13 张缺失（Half/Final1-10 结局立绘、李岸.png、Happy End.jpg、旧上海滩Title.jpg），需占位图兜底

### 需求2（剧情分支图）：可行，工作量偏大
- 纯 CSS 不现实，用 SVG（构建期脚本静态生成，或 viz-js/d3-dag 布局）
- 图规模：66 个剧情节点 + 129 条 jump 边 + 139 个 game_over 终点，层次布局可行但需调边交叉
- 点击节点放大详情 + 跳转速览版对应位置：可行
- 难点同上：条件边需特殊标注（同一跳转多目标）
